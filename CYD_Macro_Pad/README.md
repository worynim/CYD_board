# CYD 무선 매크로 패드 (Wireless Macro Pad)

CYD 보드(**ESP32-2432S028**, 2.8" 320x240 터치 LCD)를 **무선 매크로 패드(Stream Deck 클론)** 로 바꾸는 프로젝트.

화면에 4×3 터치 버튼 그리드가 보이고, 버튼을 누르면 Wi-Fi(UDP)로 Mac 호스트에 이벤트가 전달된다. 호스트는 설정된 액션을 실행한다.

- **키보드 단축키** (예: `cmd+shift+4`, **`f5`**, `cmd+shift+f3` — 기능키 **F1~F20** 지원)
- **문구/텍스트 입력** (한글 포함, IME 무관 — 클립보드 + Cmd+V 방식)
- **앱 실행 / URL 열기** (예: `Google Chrome`, `https://claude.ai`)

기본 2페이지 × 12버튼 = 총 24버튼 (최대 **8페이지 = 96버튼**). 버튼 **라벨·동작·색상**은 호스트 GUI에서 편집하고, 설정을 적용하면 디바이스에 즉시 반영된다. 페이지 이름도 자유롭게 바꾸고 페이지를 추가/삭제할 수 있다.

**주요 기능**

- **페이지 탭 드래그 순서 변경**: 페이지 탭을 마우스로 끌어 순서를 바꿀 수 있고, 놓는 즉시
  디바이스에도 자동으로 반영된다 (설정 적용 불필요).
- **페이지 이동 롤링**: 상태바 좌/우 화살표로 페이지를 넘기는데, 마지막 페이지에서 `Next` →
  첫 페이지, 첫 페이지에서 `Prev` → 마지막 페이지로 **순환** 이동한다.
- **이미지 버튼 / 한글 라벨**: 버튼에 이미지를 업로드하거나, 라벨을 한글로 쓰면 호스트가
  71×61 이미지로 렌더링해 보내준다 (기본 폰트의 한글 미지원 우회). 고품질 유지(품질 하한 70)를
  보장하고, 1400B를 넘는 이미지는 여러 UDP 패킷으로 나눠 전송한다 (MIMG fmt=2 청킹).
- **둥근 모서리 버튼**: 이미지 버튼도 텍스트 버튼과 동일한 반경(R=10)의 둥근 모서리로 그려진다.
  JPEG의 4:2:0 서브샘플링은 이미지의 깎인 모서리를 각지게 뭉갤 수 있어서, 펌웨어가 버튼을
  그릴 때 배경색으로 모서리 4곳을 직접 깎는다 (`roundButtonCorners`).
- **실행 결과 피드백**: 버튼을 누르면 호스트의 액션 성공/실패에 따라 해당 버튼이 초록/빨강으로
  ~300ms 점멸한다 — 실행됐는지 바로 알 수 있다.
- **백라이트 자동 조절**: GPIO34의 CDS 조도 센서로 주변 밝기를 읽어 화면 밝기를 자동 조절하고,
  60초 무터치 시 밝기만 낮춘다 (off 아님, 터치하면 복귀).
- **이동형 프로필**: 설정을 JSON으로 **내보내기/가져오기**하거나, **디바이스에서 불러오기**로
  보드에 저장된 전체 프로필(라벨·색·페이지 이름·액션 포함)을 새 PC에서 한 번에 복원한다.
- **마지막 페이지 복원**: 종료 시 사용하던 페이지를 부팅 때 복원한다.
- **디바이스 내장 저장**: 전체 설정과 버튼 이미지를 LittleFS에 저장 — 호스트가 꺼져 있어도
  부팅/페이지 전환 시 이전 화면이 그대로 복원된다 (오프라인 동작).

## 프로젝트 구조

```
CYD_Macro_Pad/
├── CYD_Macro_Pad/
│   └── CYD_Macro_Pad.ino            # ESP32 펌웨어 (단일 파일, Arduino IDE)
└── host_macro_pad/
    ├── macro_pad_gui.py             # 호스트 GUI (설정 편집 + UDP 리스너 + 액션 실행)
    ├── _input_helper.py             # 키보드 입력 격리 헬퍼 (pynput 전용 서브프로세스)
    ├── requirements.txt             # pynput (+ Pillow — 버튼 이미지/한글 라벨 렌더링용)
    └── macro_config.json            # 설정 파일 (이미지 base64 포함, 실행 시 자동 생성, gitignore 대상)
```

## 시작하기

### 1. 펌웨어 업로드 (Arduino IDE)

1. `CYD_Macro_Pad/CYD_Macro_Pad.ino`를 Arduino IDE로 연다.
2. **보드:** `ESP32 Dev Module` · **Flash:** `4MB (32Mb)` · **업로드 속도:** `921600` (불안정하면 `115200`)
   **파티션:** `Huge APP (3MB No OTA/1MB SPIFFS)` **권장** — 단, **필수는 아니다.** 데이터 파티션이 있는
   스킴(예: 기본 `Default 4MB`, SPIFFS 1.5MB)이면 내장 저장(LittleFS)까지 그대로 동작한다.
3. 라이브러리 매니저에서 **LovyanGFX**, **JPEGDEC** 설치 (버튼 이미지/한글 라벨 디코딩용).
4. 업로드 후 시리얼 모니터(115200)에서 `[WiFi] Connected!` + `[AsyncUDP] Listening on port 8890` 확인.

> 첫 부팅 시 Wi-Fi를 터치로 설정한다: AP 목록 선택 → 가상 키보드로 비밀번호 입력 → NVS에 저장.
> 나중에 바꾸려면 **하단 바를 2.5초 길게 누르면** 재설정 화면이 열린다.
>
> 파티션의 **데이터(SPIFFS) 영역**은 펌웨어가 **LittleFS**로 마운트해 전체 설정(`/config.bin`)과
> 버튼 이미지(`/btns/`)를 저장한다 (스킴에 따라 크기 상이 — Huge APP은 1MB, Default 4MB는 1.5MB).
> 이 저장 덕분에 호스트가 꺼져 있어도 부팅/페이지 전환 시 이전 화면이 그대로 복원되고,
> 이미지 버튼도 플래시에서 즉시 로드된다.

### 2. 호스트 실행 (Mac)

```bash
cd "CYD_Macro_Pad/host_macro_pad"
pip install -r requirements.txt
python3 macro_pad_gui.py
```

> **macOS 접근성 권한 (필수):** 키보드 입력(pynput)은 호스트 GUI가 아니라
> 격리된 헬퍼 프로세스(`_input_helper.py`)에서 수행된다. 키보드를 제어하려면
> **시스템설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 터미널(또는 Python)을 켜야 한다.
> 권한이 없으면 단축키/문구 액션이 조용히 무시된다.
>
> **크래시 격리:** pynput은 네이티브(Quartz) 코드라 드물게 프로세스를 통째로 죽일 수 있다.
> 그래서 키보드 입력은 항상 별도 서브프로세스에서 실행된다 — 헬퍼가 죽어도 GUI는
> 살아남고 이벤트 로그에 실패만 표시한다.

### 3. 버튼 설정

1. 호스트 GUI에서 각 버튼의 **라벨**, **동작**, **색상**을 입력한다.
   - 동작 종류: `shortcut` / `text` / `app/URL` (`app`은 **앱 실행 + URL 열기** 공용)
   - 색상: 10색 팔레트(gray/red/orange/yellow/green/teal/blue/purple/pink/white) — 버튼 구분용
   - 빈 라벨·액션 입력칸에는 힌트(**"이름"**, **"액션"**)가 흐리게 표시되어 무엇을 넣는 칸인지 알 수 있다.
   - 예: 라벨 `Copy` + `shortcut` + `cmd+c` / 라벨 `인사` + `text` + `안녕하세요!` / 라벨 `Chrome` + `app/URL` + `Google Chrome`
   - **이미지 버튼**: 카드의 `🖼` 버튼으로 이미지를 업로드하면 버튼 모양이 그 이미지(71×61
     중앙 크롭)가 된다. `✕`로 제거하면 다시 텍스트 버튼으로 돌아온다. **라벨을 한글로 써도**
     호스트가 이미지로 렌더링해 표시되므로 걱정 없이 쓸 수 있다.
   - **사용법 안내**: 우측 상단의 **`?`** 버튼을 누르면 사용법 창이 열린다 — URL 입력 방법,
     단축키에 쓸 수 있는 특수키 목록, macOS 접근성 권한 등이 정리되어 있다.
2. **페이지 이름**은 상단 입력란에서 바로 바꾸고, **+ 페이지 / − 페이지**로 추가·삭제한다 (1~8페이지).
   **페이지 탭을 마우스로 끌면 순서를 바꿀 수 있고**, 놓는 즉시 디바이스에 자동 반영된다.
   디바이스 상태바에 **페이지 이름 + x/y**로 표시된다.
3. **💾 설정 적용 (Apply)** 클릭 → 디바이스에 라벨·색상·액션이 반영되고, 내장 저장(LittleFS)에
   기록된다.
4. **리스너는 프로그램 시작 시 자동으로 동작**한다 — 버튼을 누르면 바로 액션이 실행되고,
   성공/실패에 따라 버튼이 초록/빨강으로 잠깐 점멸한다.
5. **백업/이동:** `⬇ 내보내기`로 설정을 JSON 파일로 저장하고 다른 PC에서 `⬆ 가져오기`로 복원한다.
   보드에 이미 저장된 프로필은 **🖥 디바이스에서 불러오기**로 그대로 가져와 Apply할 수 있다.

> **IP를 몰라도 된다.** 호스트는 시작 즉시 UDP `8890` 리스너를 띄우고, 디바이스가 3초마다
> 보내는 비콘(`MPBE`)을 받으면 IP를 자동으로 학습한다. (같은 네트워크 전제. 다른 네트워크면
> 자동 검색이 불가 — 방화벽/라우터 설정이 필요할 수 있다.)
>
> **동기화는 가볍게:** 비콘마다 전체 설정을 다시 보내지 않고, 호스트가 작은 ACK(~12B,
> `MCFG count=0`)만 회신해 디바이스가 호스트 IP/포트를 갱신한다. 전체 설정+이미지 푸시는
> ① Apply ② 호스트 시작 시 ③ 새 디바이스 발견 시에만 일어난다. 호스트 IP가 바뀌어도
> 재실행 없이 비콘→ACK로 자가치유되고, 디바이스는 LittleFS 저장이라 재부팅 후에도 복원된다.
>
> **한글 라벨:** 버튼 라벨은 기본 폰트에 한글 글리프가 없지만, 한글로 쓰면 호스트가 이미지로
> 렌더링해 전송하므로 그대로 표시된다. (한글 **페이지 이름**은 상태바 기본 폰트의 한계로
> 영문만 표시된다.) 한글 **문구 입력**은 액션으로 그대로 동작한다.

## 와이어 프로토콜 요약 (v3)

모든 패킷은 포트 `8890`, 헤더 `>IBBBB`(magic u32 + 4×u8). 설정 관련 패킷은 **여러 UDP 패킷으로
분할**될 수 있다 — `count`로 한 페이지의 버튼 수를 표시하고, 페이지 이름은 첫 청크에만 실린다.

| 패킷 | 방향 | magic | 헤더 필드 + 페이로드 |
|------|------|-------|----------------------|
| 설정 (MCFG) | 호스트 → 디바이스 | `0x4D434647` | `page`, `count`, `num_pages`, `0` + `page_name_len u8`+이름(≤20) + 버튼별 `>BBBBB`(id, 라벨길이, color_idx, action_type, 액션길이)+라벨+액션값(≤128) |
| 설정 요청 (MREQ) | 호스트 → 디바이스 | `0x4D524551` | `0,0,0,0` — 디바이스가 위 MCFG 포맷으로 전체 덤프 회신 |
| 이미지 (MIMG) | 호스트 → 디바이스 | `0x4D494D47` | `page`, `button_id`, `format`, `0` + JPEG 바이트. `format=0`=JPEG(≤1400B), `format=1`=이미지 제거→텍스트 폴백, `format=2`=**청킹** — `>IHH`(총길이, 총청크, 청크idx) 서브헤더 + ≤1400B 청크 (1416B < MTU, 단편화 없음) |
| 피드백 (MPOK / MPER) | 호스트 → 디바이스 | `0x4D504F4B` / `0x4D504552` | `page`, `button_id`, `0`, `0` — 액션 성공/실패 플래시 |
| 이벤트 (MPAD) | 디바이스 → 호스트 | `0x4D504144` | `page`, `button_id`, `0`, `0` |
| 비콘 (MPBE) | 디바이스 → 브로드캐스트 | `0x4D504245` | `0,0,0,0` |

- `action_type`: `0`=shortcut, `1`=text, `2`=app. 디바이스는 액션을 **저장만** 하고 실행은 항상
  호스트가 한다 (pynput/pbcopy는 호스트 전용 — 크래시 격리 유지).
- **ACK:** 비콘 수신 시 호스트는 `MCFG count=0`(설정 없음)으로 회신 → 디바이스가 소스 IP/포트만
  학습한다. 전체 설정/이미지 푸시는 Apply·호스트 시작·새 디바이스 첫 비콘 시에만.
- 디바이스는 **가장 최근 설정 패킷의 소스 IP/포트**로 이벤트를 전송한다.
- **자동 검색:** 디바이스가 3초마다 서브넷 브로드캐스트로 `MPBE` 비콘을 보낸다. 호스트가 이를
  받으면 CYD IP를 자동으로 학습하고 ACK를 회신한다. → **같은 네트워크라면 IP를 몰라도 된다.**
  (자동 검색은 라우터를 못 넘는다 — 다른 네트워크면 별도 설정 필요.)
- **내장 저장:** 전체 설정은 디바이스 LittleFS `/config.bin`, 버튼 이미지는 `/btns/p{page}_{bid}.jpg`에
  저장된다. 부팅 시 이 파일들로 화면을 복원한다.
- **색상 팔레트:** `color_idx`는 호스트 `COLOR_NAMES`/`COLOR_HEX`와 펌웨어 `BTN_PALETTE`가
  순서·값 정확히 일치해야 한다 (10색: gray/red/orange/yellow/green/teal/blue/purple/pink/white).
  팔레트는 **인덱스로 전송**되므로 표시 이름을 바꿔도 (예: `slate`→`gray`) 와이어 호환성은 유지된다.
- 공유 상수: `MAX_PAGES=8`, `GRID_COLS=4`, `GRID_ROWS=3`, `BUTTONS_PER_PAGE=12`, `LABEL_MAX=24`,
  `PAGE_NAME_MAX=20`, `ACTION_VAL_MAX=128`. (초기 페이지 수는 호스트 `DEFAULT_PAGES=2`, 펌웨어
  `numPages` 초기값과 일치.)
- 자세한 계약은 저장소 루트의 `CLAUDE.md`를 참고.

## 팁 / 트러블슈팅

- **버튼을 눌렀는데 아무 일도 없나요?** → 버튼이 **빨강으로 점멸**하면 액션 자체가 실패한 것 —
  호스트 리스너 상태와 접근성 권한(손쉬운 사용)을 확인한다. 점멸조차 없으면 디바이스↔호스트가
  같은 네트워크인지 확인한다.
- **디바이스 라벨이 안 바뀌나요?** → 호스트 CYD IP가 디바이스와 같은 네트워크인지, Apply를 눌렀는지 확인.
- **단색 버튼/라벨이 얼룩덜룩하게 보이나요?** → 과거엔 JPEG 4:2:0 크로마 서브샘플링이 텍스트·모서리
  경계를 뭉갠 게 원인이었다. 현재 호스트는 **4:4:4 + 품질 90**로 저장해 대부분 사라졌다.
  용량이 커도 **품질 하한 70**을 보장하고, 1400B를 넘는 이미지는 여러 UDP 패킷으로 나눠
  전송하므로(MIMG `fmt=2`) 화질 저하 없이 전달된다.
- **화면이 갑자기 어두워졌나요?** → 60초 무터치 디밍이다(off 아님). 터치하면 원래 밝기로 복귀하고,
  평상시엔 주변 조도(CDS)에 맞춰 밝기가 자동 조절된다.
- **"디바이스에서 불러오기"가 안 되나요?** → 아직 비콘으로 IP가 검색되지 않았을 수 있다. 잠시 기다린
  후 다시 시도 (리스너가 시작되고 3초 주기 비콘을 수신해야 한다).
- **액션이 느리게 동작하나요?** → UDP는 fire-and-forget이라 보통 즉시 동작한다. 버튼 탭 사이에 15ms 폴링 스로틀이 있다.
- **Wi-Fi가 바뀌었나요?** → 하단 바를 2.5초 길게 눌러 재설정.
- **오프라인 패킷 검증:** `python3 macro_pad_gui.py --test-packets`
- **오프라인 액션 검증 (디바이스 없이):** `python3 macro_pad_gui.py --test-action shortcut cmd+c` 또는 `--test-action text 안녕` — 격리 헬퍼 경로로 키보드 입력이 실제 동작하는지 확인한다.
